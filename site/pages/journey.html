Engineering journey

Keep the reasoning history, including wrong turns.

Entry 001

We were about to implement GameState too early.

The original plan moved directly from repo setup to a Pydantic GameState. While reading it, a more basic question appeared: how could we decide the schema before studying what demos and realistic live sources actually expose? That question moved the project back into source discovery.

Entry 002

The problem had to come before the schema.

Even source discovery was not enough. The project still had not decided what the first model was supposed to predict. V0 became A Plant / B Plant / No Plant forecasting because the target is objective and can validate the full offline-to-online ML system.

Entry 003

Many exciting ideas appeared.

Transcript, self-hosted CS2, synthetic FPS environments, utility knowledge, and player communication all expanded the long-term vision. Instead of adding them to V0, they were placed into future research.

Entry 004

Versions should be driven by evidence.

The project adopted a new discipline: finish a frozen version, record problems and failures, evaluate them, and then use that evidence to design the next version rather than redesigning the current version continuously.
